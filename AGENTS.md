# Public cloud-development instructions

- Work in the cloud and keep source on the account owner's GitHub, `ai2chiuo`. Verify the authenticated owner before writing. Do not use another connected account.
- Work on one bounty at a time. The initial implementation effort is bounded to one 90-minute attempt, within the user's existing included Codex usage; stop and report if usage or access is unavailable. Do not buy credits or use billable API keys.
- Before any implementation, read the current https://make.fun/skill.md and the bounty's requirements. Verify that complete native development logs, provider usage and the required instruction context can be exported by the official kit. Keep records genuine and unchanged; never reconstruct sessions or disguise an agent-started run as person-started.
- Use public research and official specifications; write original entry code. Do not copy a competing entry, existing engine, reference implementation or generated answer table into the entry.
- Use a separate fresh GitHub repository for every bounty, created only after it opens. Keep the development kit and bulky tests outside size-limited entry roots. Read the official freshness rules before initializing.
- Tests run in a cloud environment and on GitHub Actions. Keep meaningful correctness, determinism, resource and output-format checks. Report actual results, not guessed scores or ranks.
- Free entries only. Before a submission, all official checks must pass, the quota must allow it, and the real account must be `freeway`. Do not expose, request in public, or commit credentials. A local authorized delivery process may handle signing and upload after retrieving the genuine cloud records.
- No trading, wallet payments, third-party social posts, purchased services, or messages to other people.
- Keep the highest verified qualifying result. Read the competition's final-entry rule before sending another version: some competitions make the latest entry final. Do not risk replacing a valid entry with an untested one.
- When a run completes, report the repository and full commit SHA, cloud task ID/URL, native-record export method, actual test results, and any submission receipt. Do not claim a bounty was entered without the official receipt.
